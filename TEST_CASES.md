# Test cases: Booking Risk Review

Written by QA from the spec (README.md, CLAUDE.md domain rules, JOURNEY.md past bugs), not from
the code. A reviewer can follow each row by hand in the running app (`npm run dev`) or check the
automated test named in the last column.

**Status** says whether an automated test proves the row:

- **Covered**: a test that existed before QA checks it (file and test name given).
- **Covered (QA)**: a gap that the QA suite now covers (`*.qa.test.ts(x)` in Vitest, `e2e/` in
  Playwright).
- **Bug**: the QA test exists and fails because the app disagrees with the spec. It is marked
  `it.fails` / `test.fail()` with a `BUG` comment, so the suite stays green until the app is fixed.
- **Gap**: still not automated: manual checks and known limitations.

**Type**: unit (pure function or hook), component (React Testing Library in jsdom), E2E
(Playwright, real Chromium), manual (needs a human: contrast, screen reader).

**Common preconditions**

- **Fresh data**: the original 12 bookings and default switches. In the app: Demo controls → Reset
  demo data. In Vitest: `resetApi()` then `configureApi({ delayMs: 0 })`.
- **Mock bookings used below**: BK-1007 Jordan Alcott (high 65, suggest verification), BK-1008
  Ryan Kessel (high 90, suggest decline), BK-1009 Noor Haddad (ID pending), BK-1010 Victor Sandoval
  (130 raw, capped at 100, ID failed), BK-1001 Dana Whitfield (low 0), BK-1005 Tovah Mercer
  (verification requested), BK-1011 Amelia Choi (approved), BK-1012 Trent Yoakum (declined).
- **Starting counts**: Needs review 9, Verification requested 1, Approved 1, Declined 1 (9/1/1/1).

**Test file shorthand**: `score` = `lib/scoreBooking.test.ts`, `rec` = `lib/recommendAction.test.ts`,
`trans` = `lib/transitions.test.ts`, `sort` = `lib/sortQueue.test.ts`, `api` =
`api/bookingsApi.test.ts`, `hook` = `hooks/useBookings.test.ts`, `page` =
`components/RiskReviewPage.test.tsx`, `drawer` = `components/ReviewDrawer.test.tsx`, `toast` =
`components/ui/Toast.test.tsx` and `useToasts.test.ts`. Paths are under
`src/features/risk-review/` unless they start with `src/` or `e2e/`.
